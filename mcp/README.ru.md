# Lookin.Team Base: MCP только для чтения

Локальная реализация для клиентов, которые умеют запускать MCP через stdio.
Python 3.9+, только стандартная библиотека: установка пакетов и сторонних
скриптов не нужна. Ядро BookStack не изменяется. Сервер не открывает порт,
не запускает shell, не создаёт агентов и не записывает файлы базы.

## Возможности

| Инструмент | Назначение |
|---|---|
| `search` | Поиск с `offset`/`count` |
| `list_content` | Полки, книги, главы, страницы, вложения, изображения |
| `read_section` | Структура конкретной полки, книги, главы |
| `read_page` | Статья в HTML, исходном HTML или Markdown |
| `read_attachment` | Исходные байты файла или внешняя ссылка |
| `read_image` | Байты изображения из галереи |
| `export_content` | Выгрузка книги/главы/страницы в HTML, текст, Markdown, PDF, ZIP |

Все обращения к BookStack — GET по фиксированным маршрутам. Произвольных URL,
HTTP-методов, инструментов записи и доступа к настройкам/пользователям нет.
Права дополнительно проверяет BookStack по личному ключу агента. Даже если
ошибочно выдать MCP более сильный ключ, инструментов записи в нём не появится;
это не отменяет требования выдавать ключ именно роли читателя.

Статьи и вложения — недоверенные данные. Указания внутри них не дают агенту
полномочий менять поручение владельца, запускать команды, раскрывать секреты
или обращаться к другим ресурсам. Клиент должен сохранять это разграничение.
Внешняя ссылка возвращается как ссылка: MCP не обходит ограничения Google Drive
и не выполняет автоматических переходов на внешние сайты.

## Запуск локального пилота

Из папки `bookstack-local`:

```sh
python3 mcp/server.py --credentials-file local-dev/private/agents/pilot-reader.json
```

Ручной запуск ожидает протокол в стандартном вводе; это не чат. Обычно клиент
запускает процесс сам. Пример его настройки — `client.example.json`: заменить
пути на реальные абсолютные пути к Python, `server.py` и личному файлу ключа.
Сам ключ не помещать в конфиг клиента, Git, чат или статьи. Переменная
`BOOKSTACK_CREDENTIALS_FILE` задаёт путь, а не секрет.

Для каждого независимого агента — свой пользователь BookStack, личный ключ и
отдельный процесс MCP. Текущий пилотный ключ не раздавать всем коллегам.
Формат защищённого JSON-файла:

```json
{
  "base_url": "http://127.0.0.1:8080",
  "token_id": "PERSONAL_TOKEN_ID",
  "token_secret": "PERSONAL_TOKEN_SECRET"
}
```

Права файла — 0600 или 0400, владелец — пользователь процесса; символьная ссылка
вместо файла запрещена. Каталог также следует закрывать правами 0700. Значения
в примере — поясняющие заглушки, не действующий ключ. Секреты создаются в профиле
соответствующего пользователя BookStack в разделе API-ключей; точные права
и порядок отзыва описаны в `../local-dev/AGENT-ACCESS.ru.md`.

Допускается HTTPS-адрес без пути либо HTTP только на числовом loopback-адресе.
Подкаталоги установки в этой версии не поддерживаются. Прокси из окружения
не используются, перенаправления отклоняются, проверка HTTPS-сертификатов
включена. Ключи, заголовки, тексты ошибок сервера и содержимое статей в лог
не записываются. stdout содержит только сообщения MCP.

## Получение больших материалов

Списки возвращаются порциями до 100 элементов. Продолжать с `offset`, пока не
получено `total`. Статья возвращается порциями до 65 536 символов; продолжать
по `next_offset`. Если статья меняется во время чтения, её лучше прочитать заново:
страницы запрашиваются заново на каждую порцию.

Вложения/изображения/выгрузки возвращают base64, `total_length`, `next_offset`,
`sha256` и `snapshot`. Декодировать порции и соединять по порядку. В следующем
запросе указывать тот же объект, формат и `snapshot` вместе с `next_offset`.
Это сохраняет целостность выгрузки, даже если повторный экспорт создаёт другой ZIP.
В конце сравнить SHA256 полного файла. Клиент решает, куда сохранить результат;
MCP сам не сохраняет полученные файлы на диск.

Одна активная копия байтов хранится в памяти процесса до следующей загрузки
или завершения процесса. Продолжать её чтение можно 5 минут. При продолжении
снова проверяются действующий ключ и доступ к исходному объекту через BookStack;
отозванный ключ не позволяет получить остаток из памяти. Начало другой загрузки
заменяет предыдущую. Предельный ответ BookStack — 80 MiB, порция MCP — 64 KiB
исходных байтов. Base64 увеличивает объём примерно на треть, а API-вложения
уже приходят в base64: крупные материалы могут упереться в этот лимит.
Это предел данной реализации, а не обещание выгружать файлы любого размера.
Для более крупных файлов понадобится отдельный потоковый способ получения.

Частота — не более 150 запросов/минуту на процесс; BookStack дополнительно
применяет свой лимит на пользователя. Ответ 429 возвращается как понятная ошибка,
без бесконечного повтора: клиенту следует подождать и повторить запрос.
Данные не передаются модели сами по себе: их получает вызвавший инструмент клиент.

## Проверки

```sh
python3 -m unittest discover -s mcp -p 'test_*.py' -v
# Только локальная действующая база, личный пилотный ключ не печатается:
python3 mcp/check_live.py
```

Проверяются протокол отдельного процесса, белый список инструментов/аргументов,
запрет записи и подстановки путей, безопасная загрузка ключа, ошибки доступа,
порционное чтение и повторная проверка прав для сохранённой в памяти выгрузки.
Живая проверка читает текущие статьи, структуру и собирает ZIP из частей,
проверяя SHA256 и целостность ZIP. Отчёт без текстов и секретов сохраняется в
`../local-dev/mcp-verification.json`. Тесты запрета API-записи на уровне роли
BookStack выполнены отдельно: `../local-dev/tests/AgentAccessTest.php`.

## Совместимость и следующие этапы

Объявлены версии протокола 2024-11-05, 2025-03-26 и 2025-06-18; реализованы
initialize, initialized, ping, tools/list и tools/call. Дополнительные функции
MCP не объявляются. Самописный клиент может использовать API напрямую.

Подключение из конкретного ChatGPT/Claude и других приложений ещё не проверено.
Этот файл конфигурации подходит только клиентам с поддержкой stdio. Облачному
клиенту, которому нужен удалённый MCP по HTTP, эта локальная команда не подходит.
Для него отдельный следующий этап — сетевой транспорт с индивидуальной
аутентификацией, HTTPS, проверкой Origin и ограничениями запросов. Это не
реализовано и не опубликовано. Не открывать текущую локальную базу туннелем.

Справочные спецификации: [stdio](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports),
[инструменты](https://modelcontextprotocol.io/specification/2025-06-18/server/tools),
[инициализация](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle).

## Главный агент в интерфейсе базы

Можно добавить в тему базы чат, видимый только владельцу: поручение → план →
выполнение → результат/журнал. Отдельная служба ведущего агента получает модель
через API и обращается к BookStack через свой доступ для записи. API-ключ модели
хранится только в службе, не в браузере. Доступ к чату и истории проверяется на
сервере, а не только скрытием кнопки в меню.

Создание помощников — функция этой службы, не BookStack. Права помощников
ограничиваются поручением, расходы/время/число помощников имеют лимиты; нужна
кнопка остановки и различимые записи действий. Работа с материалами, управление
сервером и управление доступом — отдельные полномочия.

Для работающего чата пока не выбраны модель, API-провайдер, бюджет и канал
поручений владельца. Текущий этап не добавляет фиктивную кнопку чата и не
запускает службу ведущего агента. Подробная схема сохранена в
`../local-dev/AGENT-ACCESS.ru.md`.
