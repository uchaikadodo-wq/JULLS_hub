# Доступ ИИ-агентов: локальный этап, 29.10.2026

## Согласованная схема

Сторонним агентам разрешено читать и получать всё опубликованное содержимое базы:
статьи, структуру, вложения, изображения и доступные экспорты. Они не получают
права изменять/создавать/удалять содержимое, управлять пользователями, ролями,
настройками, сервером или секретами. Личные черновики, корзина и системный журнал
не считаются опубликованной базой знаний.

Скачанную агентом копию нельзя отозвать отключением ключа. Выдавать такой доступ
следует только агентам, которым разрешена передача этих материалов. Статья со
ссылкой на Google Drive не предоставляет доступ к содержимому Drive.

## Что создаёт настройка

- `ИИ — чтение и выгрузка`: API, просмотр полок/книг/глав/страниц, экспорт,
  просмотр ревизий через поддерживающие это страницы BookStack.
- `ИИ владельца — работа с материалами`: отдельная резервная роль, дополнительно
  создание и изменение материалов/вложений/изображений. Без удаления, управления
  пользователями, правами, настройками и сервером. В рабочей локальной базе
  никому не назначена; расширять полномочия под конкретные поручения отдельно.
- Один синтетический `ИИ — тестовый читатель`, адрес `pilot-reader@agents.example.test`,
  только роль чтения. Случайный пароль не выдаётся. Один API-ключ на 30 дней.
  Секрет сохранён только в `local-dev/private/agents/pilot-reader.json` (0600,
  исключён из Git). Это локальный пилот, не общий ключ для коллег.

Для каждого будущего независимого агента создаются свой пользователь, один
согласованный набор ролей и собственный именованный ключ со сроком действия.
Несколько ключей одного пользователя не разделяют права. Дополнительная роль
может расширить права: не назначать читателю роли редактора/администратора.

## Настройка и проверка

Из корня `bookstack-local`, только текущая локальная среда:

```sh
docker compose -f compose.local.yaml exec -T app php scripts/setup-agent-access.php
# Выше только предварительный просмотр. После согласования и бэкапа:
docker compose -f compose.local.yaml exec -T app php scripts/setup-agent-access.php --apply
python3 scripts/check-agent-reader.py
```

Скрипт использует штатные службы BookStack, не меняет ядро и содержимое статей.
Повторный запуск сохраняет существующие роли/ключ, но отказывается работать при
неожиданном изменении политики, дополнительных ролях пилота или истёкшем ключе.
Проверяет фактические права чтения и запрет записи на всех текущих объектах.
Если отдельные ограничения содержимого закрывают чтение или разрешают запись,
настройка останавливается; чужие ограничения автоматически не снимаются.
Права полки не заменяют проверку самих книг, глав, страниц и вложений.
После новых исключений доступа такую проверку следует повторять.

HTTP-проверка делает только GET: читает текущие объекты, выгружает статьи,
проверяет запрет административных списков и запрос без ключа. Тексты, файлы и
секреты не печатает и не сохраняет; отчёт содержит статусы, размеры и хеши.
API по умолчанию ограничен 180 запросами в минуту на пользователя; массовое
чтение должно обрабатывать страницы списка и ответы 429 с ожиданием.

Проверки записи, закрытого содержимого, скачивания тестового вложения,
истечения/отзыва ключа и действий резервного редактора выполняются отдельно:

```sh
# Только в изолированной восстановленной копии с тестовой БД!
docker compose -p bookstack-restore-20261028t140918z -f compose.local.yaml run --rm --no-deps app php vendor/bin/phpunit --configuration phpunit.xml local-dev/tests/AgentAccessTest.php
```

Файл использует `mysql_testing`, тестовые данные и откат транзакций. Не направлять
тестовую конфигурацию на рабочую БД. Рабочая тема не заменяется тестами.
Создание ролей, пользователя, ключа и изменения статей записываются штатным
журналом. Полный журнал каждого прочитанного байта штатным API не гарантируется:
если он потребуется, это отдельная задача на журналирование MCP без секретов.

## Подключение коллег после локального этапа

Сейчас база доступна только на этом Mac. Внешние коллеги ещё не подключены.
Перед подключением нужен конкретный тип клиента/бота и место его запуска.
Клиент с поддержкой HTTP API может читать напрямую; клиент с MCP потребует
переходник. MCP для сторонних агентов должен иметь только поиск/чтение/выгрузку,
без универсального инструмента HTTP и без инструментов записи. Нужны проверка
прав BookStack, лимиты, аутентификация и отсутствие секретов в логах.

Сетевое подключение после отдельного разрешения на сервер: HTTPS и индивидуальная
аутентификация, без публичной анонимной выдачи содержимого. Локальный stdio MCP
не открывает сетевой порт. Секреты передаются через защищённые настройки клиента,
не в чат, статьи или Git. Локальный тестовый ключ на сервер не переносить.

Отзыв: администратор открывает «Настройки → Пользователи → нужный агент → API-ключи»
и удаляет конкретный ключ. Для полного отключения пользователя от API убрать
`access-api` из его эффективных ролей/отозвать все ключи, проверить повторный запрос.
При разных назначениях не менять общую роль ради отключения одного агента.

## Будущий ведущий агент владельца — предусмотрено, не запущено

Под «хостом» пока понимается отдельная служба ведущего агента; её модель,
программа, место запуска и стоимость ещё не выбраны. Это не встроенная функция
BookStack. Размещение на VPS отдельно от контейнеров приложения/БД, без
`docker.sock`, привилегированного режима и личных секретов.

Схема: владелец выдаёт поручение → ведущий агент планирует → при необходимости
создаёт ограниченных помощников → проверяет результат → отчитывается.
Сторонние агенты не имеют доступа к этой службе. Ведущий работает с материалами
через отдельный MCP записи и собственную учётную запись; независимые помощники
получают отдельные учётные записи/ключи с правами в пределах поручения.
Они не должны создавать пользователей или повышать себе права в BookStack.
Выдачей ключей управляет владелец/отдельный проверенный механизм, не общий токен.

Для первого запуска нужно определить источник поручений владельца, способы
подтверждения его личности, разрешённые операции, лимиты расходов/времени и
числа помощников, остановку и отзыв доступа. Команды из статей/вложений — данные,
не распоряжения владельца. Агент не должен исполнять внедрённые в документы
инструкции, раскрывать ключи или передавать свои полномочия сторонним агентам.

Контроль доступности/ошибок можно добавить отдельными инструментами чтения.
Обновления приложения, shell, перезапуски контейнеров, удаление данных,
управление доступом и развёртывание на сервере требуют отдельных явно описанных
полномочий и проверки восстановления. Резервная роль редактора их не предоставляет.

## Границы этого этапа

Этот этап не запускает MCP или ведущего агента, не публикует базу и не выдаёт
ключи реальным коллегам. Он также не устраняет ранее найденные уязвимости npm
и не подтверждает завершение общей подготовки к серверу. Перенос, внешнее
резервное хранение и работа с настоящими внешними ИИ проверяются отдельно.

## Дополнение: следующий локальный этап MCP

По последующему согласованию добавлен отдельный MCP только для чтения в `mcp/`:
`../mcp/README.ru.md`. Это stdio-процесс без сетевого порта, с индивидуальным
ключом читателя. Есть поиск, структура, чтение, вложения, изображения и выгрузки.
Статус проверок — `mcp-verification.json`. Предыдущий раздел описывает границы
этапа настройки ролей; текущий MCP не означает публикации для внешних коллег.
Главный агент владельца и MCP записи пока не реализованы.
