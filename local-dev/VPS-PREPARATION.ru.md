## Административный доступ

Создан пользователь `ltadmin`, вход только по подготовленному ED25519-ключу.
У него нет пароля; для обслуживания настроено `sudo` без дополнительного пароля.
Это полноценный администратор с возможностью получить root, а не ограниченный
пользователь приложения/ИИ. Ключ нельзя выдавать сторонним агентам или коллегам.
В группу `docker` пользователь не добавлялся; Docker управляется через sudo.

Свежий вход и sudo проверены до отключения прежнего доступа, затем проверены
повторно после изменения SSH и перезагрузки. Закрытый ключ остался на Mac вне
bind mount приложения: `../../.server-access/` (каталог 0700, ключ 0600), вне Git.
В SSH отключены использование локального agent и переадресация портов/agent/X11.
Ключ сервера фиксирован и проверяется строго; отпечаток сохранён в `VPS-ACCESS.ru.md`.

Настройки `/etc/ssh/sshd_config.d/00-lookin-hardening.conf`:

- `PermitRootLogin no`, `PasswordAuthentication no`,
  `KbdInteractiveAuthentication no`, `PubkeyAuthentication yes`;
- `AllowUsers ltadmin`, `MaxAuthTries 3`, `LoginGraceTime 30`;
- отключены forwarding agent/TCP/X11.

Синтаксис проверен `sshd -t`, действующие значения — `sshd -T`. Служба SSH
перезагружена через reload. Первоначальный root-пароль не менялся: вход через
VNC провайдера остаётся способом восстановления, но через SSH root не допускается.

## Сетевой экран

UFW включён для IPv4/IPv6, входящие соединения по умолчанию запрещены,
исходящие разрешены. Для `22/tcp` настроено ограничение частоты новых соединений.
80/443, база данных и MCP пока не открывались. Наличие внешнего firewall
провайдера этой проверкой не подтверждалось.

Перед изменениями запланирован автоматический откат через 5 минут. После
успешного нового подключения таймер отменён. Исходные SSH/UFW-конфиги и логи
установки находятся на VPS в `/root/lookin-prep-20261029/` с закрытым доступом.

Важно: [Docker предупреждает](https://docs.docker.com/engine/install/ubuntu/),
что опубликованные контейнерные порты могут обходить правила UFW. На этом этапе
контейнеров нет. При последующем развёртывании нужно отдельно проверить
публикации портов и правила forwarding; не публиковать БД/MCP напрямую и не
считать одно включение UFW достаточной изоляцией Docker.

## Как владельцу войти с Mac

В обычном Терминале выполнить:

```sh
bash "/Users/juliaseagull/Documents/ChatGPT/База знаний лт/bookstack-local/scripts/vps-login.sh"
```

Скрипт использует нужный ключ и проверенный ключ сервера. Команда
`ssh root@194.135.23.218` с прежним паролем теперь не должна работать — это
ожидаемая защита. Не отключать проверку ключа сервера ради устранения ошибки.

При потере ключевого доступа: войти в VNC через кабинет провайдера, затем root
с сохранённым паролем. Через консоль можно восстановить ключ в
`/home/ltadmin/.ssh/authorized_keys` (владелец ltadmin, каталог 0700, файл 0600).
Не запускать восстановление настроек вслепую: сначала проверить причину ошибки.
Восстановление полного VPS по бэкапу этим этапом не настраивалось.

## Обслуживающие файлы

`../scripts/vps-prepare.py` содержит фазы именно этого согласованного этапа.
Они привязаны к IP, проверенному host key и имени сервера, отказываются
перезаписывать исходные файлы настроек. Первые фазы выполнялись через root;
после защиты они не предназначены для повторного запуска. После настройки
использовать `final-status` для чтения состояния, `vps-login.sh` для обычного входа.
