# Зашифрованные копии VPS

Состояние на 30.10.2026: создан первый зашифрованный снимок на самом VPS.
Это ещё не защита от потери VPS: загрузка на Google Drive и расписание не включены.
Компания разрешила Google Drive; отдельную авторизацию сервера ещё нужно настроить.
Подключение Google Drive в Codex не даёт серверу постоянного доступа к Google.

## Создание

На VPS установлен пакет Ubuntu `age=1.1.1-1ubuntu0.24.04.3`.
Скрипт `scripts/backup-vps.py` запускается на VPS от root, установлен как
`/opt/lookin-base/operations/backup-vps.py`. Запуск вручную:

```sh
sudo python3 /opt/lookin-base/operations/backup-vps.py
```

Скрипт ненадолго останавливает web/app для согласованности БД и файлов.
Возобновляет их работу и при ошибке снимка. Остановка или запуск Docker тоже могут
завершиться с ошибкой: после выполнения нужно проверить доступность сайта.
База данных не останавливается. В снимке SQL, хранилище вложений, конфигурация,
секреты с исходным APP_KEY, номера ревизий и контрольные суммы.
Образы приложения и исходники восстанавливаются отдельно по зафиксированным версиям.
Кэш, сессии и журналы приложения не включены.

Временные незашифрованные файлы создаются только на VPS в закрытой папке;
после попытки резервного копирования папка удаляется. При аварийном завершении
процесса следует проверить оставшиеся `.work-*` вручную. Автоматическое удаление
старых снимков пока отключено, поэтому нужно следить за свободным диском.

Итоговые файлы: `/opt/lookin-base/backups/encrypted/*.tar.gz.age` и `.sha256`.
Сервер хранит только открытый ключ шифрования `secrets/backup-recipient.txt`.
Закрытый ключ находится отдельно на Mac, вне репозитория:
`../.server-access/recovery/backup-age-identity.txt`.
Это небольшой ключ, а не локальная копия документов. Его необходимо сохранить
в согласованном менеджере секретов: без него копии расшифровать нельзя.
Не загружать закрытый ключ рядом с копиями или в GitHub.

## Проверка

`scripts/verify-vps-backup.py` запускается на Mac. Передаёт закрытый ключ через SSH
в стандартный ввод age, не записывая его на диск VPS. Проверяет контрольные суммы
и пробует импорт SQL в отдельный временный MySQL без сети и опубликованных портов.
Сверяет число строк во всех таблицах. Рабочая БД при этом не изменяется.
Тестовая БД, расшифрованные файлы и контейнер удаляются после проверки.
Отчёт: `local-dev/vps-encrypted-backup-verification.json`.

Этот тест не заменяет загрузку/скачивание копии из Google Drive и полноценную
проверку восстановленного сайта с входом и вложениями. Эти проверки нужны до
объявления внешнего резервного копирования полностью настроенным.

## Внешнее хранение — следующий шаг

Нужна авторизация Google для автоматической работы сервера, отдельная закрытая
папка и проверка записи/скачивания зашифрованного файла. Не использовать папку
договоров. Не давать средству копирования доступ ко всему Drive без необходимости.
Перед установкой клиента проверить актуальные исправления безопасности.
После успешного восстановления согласовать/включить ежедневный запуск и срок
хранения. Сбой копирования должен быть заметен владельцу.

Почта пока не отправляется (`MAIL_DRIVER=array`). Для согласованного Gmail
`u.chaika.dodo@gmail.com` нужен отдельный пароль приложения, введённый защищённо,
и проверка доставки письма. Обычный пароль Google не использовать.
